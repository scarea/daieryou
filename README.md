# 金殿棋牌

约上好友随时开一桌的棋牌平台。目前有两个游戏：

- **红中麻将**：四人，红中癞子，只能自摸，抓鸟、杀鬼翻倍。支持人机试炼（四档难度 + 教练提示 + 复盘）、快速匹配、好友约局。
- **逮二游**：三人炸金花变种，第二名才是输家。支持人机对战、快速匹配、好友约局、观战。

账号、金币、爵位、签到、任务成就、商城、好友、排行榜是平台通用的，两个游戏共享。

线上地址：<https://daieryou-royale.vercel.app>

## 架构

```
src/shared/            前后端共用
  games.ts             游戏注册表（名字、人数、图标）—— 大厅入口、牌桌列表都以它为准
  economy.ts 等        平台通用：场次、爵位、任务、商城、协议
  engine.ts / hand.ts  逮二游规则引擎
  mahjong/             红中麻将规则引擎（牌、胡牌判定、向听与进张、对局流程、视图）
src/server/
  app.ts               与运行环境无关的应用层：账号接口 + WebSocket 路由，把各游戏的牌桌服务接到一起
  accounts.ts          平台通用：用户、金币、结算、任务、商城、好友、后台、AI Key
  rooms.ts             逮二游牌桌服务
  mahjong.ts mjBot.ts  红中麻将牌桌服务与机器人
  store.ts / sqliteStore.ts / pgStore.ts   存储接口与两种实现
  main.ts              Node 入口；src/worker/index.ts 是 Cloudflare 入口
src/client/
  scenes/Lobby.tsx     平台大厅：选游戏 → 选场次 → 开一桌
  scenes/Table.tsx     逮二游牌桌
  mahjong/             红中麻将牌桌、复盘、规则
  components/Stage.tsx 舞台：电脑 1280×720；手机横屏 1280×592（竖着拿自动横置）；竖屏登录页不旋转
```

几条约定：

- **一个人同一时间只在一张桌上**，不管是哪个游戏；房号全平台唯一（9 开头的是麻将桌），所以「输入房号加入」和邀请链接不用区分游戏。
- **牌桌服务各管各的规则，对外是同一套入口**：建桌、加入、快速匹配、大厅列表、好友所在牌桌、断线重连，由 `app.ts` 统一路由。
- **服务端权威**：手牌只发给本人；麻将的视图在服务端就换算成"以自己为 0 号位"，客户端不知道绝对座位。
- **新增一个游戏**：在 `shared/games.ts` 登记 → 写规则引擎（shared）→ 写牌桌服务并在 `app.ts` 接上 → 写牌桌场景并在 `App.tsx` 接上。

## 快速开始

```bash
npm install
npm run dev
```

打开 <http://localhost:5173> 即可。`npm run dev` 会同时启动游戏服务器（8787）与前端开发服务器（5173）。

生产部署（单进程，同时提供接口、WebSocket 与静态页面）：

```bash
npm run build
npm start          # http://localhost:8787
```

环境变量：`SERVER_PORT`（默认 8787）、`DB_PATH`（默认 `data/daieryou.db`）。需要 Node.js ≥ 22.13（使用内置 `node:sqlite`，无原生依赖）。

> 如果 5173 端口被其他项目占用，Vite 会自动换到下一个端口，以终端输出的地址为准。

## 线上部署（Vercel + Cloudflare + Supabase）

| 部分 | 平台 | 地址 |
| --- | --- | --- |
| 网页 | Vercel（项目 `daieryou-royale`） | <https://daieryou-royale.vercel.app> |
| 游戏服务器 | Cloudflare Workers + Durable Object（`daieryou-royale`） | `https://daieryou-royale.<子域名>.workers.dev` |
| 数据库 | Supabase Postgres（与旧版 `daieryou` 共用同一个库，经同一个 Hyperdrive 连接） | 表名统一带 `royale_` 前缀 |

- 服务端代码与本地完全相同（`src/server/app.ts`），只是存储从 SQLite 换成 Postgres（`src/server/pgStore.ts`），入口换成 `src/worker/index.ts`。启动时自动建表。
- 网页通过构建时环境变量 `VITE_SERVER_URL` 找到游戏服务器（已在 Vercel 的 Production 环境配置）。
- 免费版 Worker 每次请求 CPU 上限 10ms，所以线上 AI 的模拟次数是本地的 35%（`BOT_SIM_SCALE`），密码哈希迭代 20000 次。
- Hyperdrive 默认会缓存只读查询约 60 秒；`pgStore.ts` 的所有读取都带 `now() is not null` 条件以绕过缓存，新增查询时请保持。
- 重新部署后，正在运行的 Durable Object 要等所有连接断开并空闲 1~2 分钟才会换成新代码（看 `/healthz` 的 `uptimeSeconds` 是否归零）。
- 无人在线一段时间后 Durable Object 会被回收，内存中的房间随之清空；账号、金币、战绩都在数据库里不受影响。

更新线上版本：

```bash
npm run deploy:server   # wrangler deploy
npm run deploy:web      # vercel deploy --prod
```

健康检查：`https://daieryou-royale.<子域名>.workers.dev/healthz`。

## 玩法

- 3 人一桌，54 张牌，**大小王是赖子**（自动变成能组成最大牌型的牌）。
- 开局每人 5 张手牌，桌面 4 张公牌（前 3 张明牌，第 4 张暗牌）。
- **第 1~4 轮**：每人选 2 张手牌 + 当轮公牌组成三张比大小；出过的牌不回手。
- 第 1~3 轮后每人摸 2 张（本轮输家先摸）；第 4 轮为暗牌回合，之后不再摸牌。
- **第 5 轮**：无公牌，剩余 3 张手牌直接比。
- **每轮第二名为输家**，分别付给头名与末位各一笔当轮基础分（1、2、3、4、5 分）；豹子对豹子的那一笔翻倍。
- 并列头名 → 第三名付分；并列第二 → 两家都付给头名；三家全平 → 不结算。
- 牌型：豹子 > 同花顺 > 同花 > 顺子 > 对子 > 散牌；A 最大，QKA 为最大顺子、A23 为最小顺子。

规则引擎在 `src/shared/`，已与旧版引擎做过 20 万组随机牌的对拍（牌型、大小、结算零差异）：

```bash
node --import tsx tests/parity.manual.ts /path/to/旧项目
```

## 红中麻将

- **联机**：快速匹配（凑齐四人立即开，12 秒等不到由机器人补）、好友约局（6 位房号或邀请链接，房主开始时空位补机器人）。真人牌桌出牌限时 20 秒、碰杠 10 秒，超时自动打出刚摸的牌；掉线或离开由机器人代打，照常结算。真人牌桌不提供教练提示。

- **规则**：112 张（万条筒 + 4 红中），红中是癞子；不能吃，可碰、杠；**只能自摸**，没有点炮和抢杠胡。
- **杠分当场结算**：补杠三家各 1 分；放杠由放杠者付 3 分；暗杠三家各 2 分。
- **抓 1 只鸟**：不分万条筒，一点 / 九点 / 红中 = 10 分，其余 = 点数 + 1，三家各付。**杀鬼**（胡牌时手里没有红中）翻倍。
- **定庄**：首局四人各掷两颗骰子，点数最大者坐庄（并列重掷）；之后赢家坐庄，流局连庄。
- 可选开关（开局面板里勾选）：七对算胡、四红中直接胡、红中可打出。
- **四档人机**：入门 / 进阶 / 高手 / 大师。因为只能自摸，没有"防守"，难度差别就是牌效算得多准、多远。
- **教练提示**：轮到你出牌时，每张牌上方显示打掉它之后的进张数，并标出推荐打法；听牌时显示在等哪些牌。
- **复盘**：每局结束逐手对比你的打法与进张最多的打法；填了 DeepSeek API Key 后可让 AI 教练写文字点评。
- **AI 教练**：在「个人中心 · AI 教练」填写自己的 DeepSeek API Key。Key 用 AES-GCM 加密后保存（密钥来自环境变量 `DATA_KEY`，本地开发自动生成在 `data/.data-key`），接口只返回掩码。
- 规则引擎在 `src/shared/mahjong/`：胡牌判定与一个独立的暴力解法做过随机对拍，并随机打 1500 局检查牌数守恒、分数零和、可重放。
- 牌面矢量图来自 [FluffyStuff/riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles)（公有领域 CC0），见 `public/tiles/CREDITS.txt`。

## 用户系统

- 账号密码注册 / 登录（PBKDF2 加盐哈希，连续输错 5 次锁定 5 分钟）。
- 游客一键试玩（起步 3,000 金币），可随时**绑定账号**保留全部金币与战绩，绑定后补齐到 5,000。
- **找回密码**：注册或绑定时发放一个恢复码（只显示一次），凭「账号 + 恢复码」重设密码；也可由管理员在后台重置。
- **防刷**：同一 IP 24 小时内最多创建 6 个游客、6 个正式账号；游客不进入风云榜。
- 会话令牌 30 天有效，服务端只保存其哈希；同一账号新登录会顶掉旧连接。
- 个人中心：改昵称、换头像、生涯数据、金币流水、账号安全。

## 积分系统

| 体系 | 说明 |
| --- | --- |
| **金币** | 一局结束按「总分 × 底注」结算；所有变动记入流水 |
| **场次** | 青云厅（底注 10）/ 鎏金阁（50）/ 龙凤殿（200）/ 凌霄殿（1,000），入场门槛为底注 × 30 |
| **荣誉 / 爵位** | 整局头名 +20、居中 +4、垫底 −12（按场次倍率）；布衣 → 乡绅 → 富贾 → 巨贾 → 王侯 → 财神 |
| **赛季** | 按自然月；换季时按爵位发放金币，荣誉分保留四成 |
| **每日任务 / 成就** | 「功名录」里领取：签到、局数、头名等每日任务，以及累计局数、豹子、爵位等成就 |
| **珍宝阁** | 用金币购买头像框、牌背、桌布（纯外观，头像框同桌可见） |
| **每日签到 / 救济金** | 连签 7 天奖励递增；金币低于 300 时每日可领 3 次救济 |
| **风云榜 / 战绩** | 荣誉榜、财富榜、常胜榜；每局逐轮牌型与输赢明细 |

## 运营后台

管理员口令在部署时通过 `ADMIN_KEY` 配置（线上已用 `wrangler secret` 设置，口令保存在本机的 `.admin-key` 文件里，该文件不进 git）。
用正式账号登录 → 个人中心 → 账号安全 → 管理员认证，输入口令后大厅左侧出现「运营后台」：
查看在线与对局统计、搜索用户、发放 / 扣除金币（写入流水）、封禁 / 解封、重置密码。
本地开发可用 `ADMIN_KEY=xxx npm run dev` 启用。

## 对局形式

- **人机对战**：一键开局，4 档 AI（新手 / 老手 / 高手 / 千王·透视）。
- **快速匹配**：凑齐 3 名真人立即开局；等待 12 秒仍不足则由机器人补位。
- **好友约战**：创建牌桌（公开或私密），凭 6 位房号或邀请链接（`/?room=房号`）加入，房主可加机器人。
- **好友与观战**：按账号加好友，或在结算页把同桌玩家加为好友；可加入好友的牌桌或观战公开牌桌（观战只能看到公开的牌）。
- **对局存档**：进行中的牌局会写入数据库，服务重启或实例被回收后自动恢复；离线的座位由 AI 托管，照常结算。
- 新手教学（5 页图解）与第一局的随局提示；背景音乐与全套合成音效；竖屏手机自动横置。
